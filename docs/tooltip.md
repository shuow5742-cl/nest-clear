# 双相机针尖对准

针尖检测和局部线性求解由 tooltip 模块提供，换针对刀流程负责采图、确认、行程守卫、PLC 通信和补偿保存。模型假设相机固定、模组位移较小，雅可比只在基准 P0 附近有效。正面相机主要观察 X/Z，侧面相机主要观察 Y/Z；像素坐标为 (u, v)，模组坐标为 (x, y, z)，单位 mm。

每个视图的目标像素为 t，2×3 雅可比 J 的单位为像素/mm。已知模组位移 d 引起的像素位移近似为 Jd。`fit_view_jacobian` 用同一参考点的位移样本最小二乘拟合 J；样本须覆盖三个独立方向。`solve_correction` 将所有视图堆叠，求解 `JΔ = t − observed`，要求视图齐全、堆叠矩阵满列秩。可指定正权重；`primary_view` 的权重额外乘二，这只是偏向主视图，并非强制 Z 完全取正面结果。§9 要求 Z 以正面为准，后续协议流程须明确实现这一策略，不能仅依赖该参数。

结果包含下一步模组修正量 Δ、各视图像素残差和伪逆投影到模组空间的残差；后者是最小范数投影，并非完整三维误差。条件数反映联合矩阵的病态程度。`axis_estimates` 固定其他轴为联合解后估计各轴，`axis_disagreement` 是各视图估计之差，受轴间耦合影响；后续流程应检查两相机 Z 分歧并按 §9 记录警告。

每轮采集两台相机并检测针尖，求解后用 `check_quality` 独立检查投影残差和条件数，调用方依据诊断决定告警或停止。质量检查不等于收敛判断：即使两视图互相矛盾，联合修正也可能接近零。`is_aligned` 判断各轴修正绝对值是否均不超过容差；未到位时，行程检查通过后移动至当前坐标 + Δ，再采图迭代。到位、检测失败、运动或位置校验失败、超过最大偏移次数等均为终止条件；失败时协议流程回 131。剪影检测器采用暗像素阈值、最大连通域和指定方向极值，受背景及遮挡影响，其置信度不是概率。

对应 [design.md §9](design.md)：40905=2 时，工具1 使用 100，工具2 使用 110。首轮验证实际位置与 P0，之后每次需要移动都按原功能码回复，PLC 到位后用同一功能码和新 Task_ID 继续。对准后回 111/121。130 时校验最终坐标，再计算 `Δ = P_final − P0`。按 §8，`pick = target + compensation`，所以新补偿 = 基准补偿 + Δ；`compute_compensation` 默认采用此约定，保留反号选项以兼容原接口。最终补偿文件的原子写入、备份、历史和即时生效属于后续协议流程；`save_baseline` 只写版本 1 的基准 YAML，不提供这些功能。

## 建立基准操作手册

1. 主程序及 PLC 完成初始化，确保处于空闲和 PLC 手动模式。在界面“对刀基准建立”按【开始对刀基准建立】，选择工具1或工具2。确认显示的工具补偿、工具偏移提示以及主、辅助对刀相机画面。
2. 用 PLC 人工点动工具使两路针尖都达到最清晰：**正面相机沿 Y 方向看 → 点动 Y 找正面最清晰；侧面相机沿 X 方向看 → 点动 X 找侧面最清晰；Z 两路都在画面竖直方向，不影响清晰度，只需让针尖在两路画面内且不靠边**（距离四边 ≥ `edge_margin_px`，默认 40 px）。不再要求针尖位于主相机视野中心，中心偏差仅作灰色参考显示。
3. 每路清晰度取最近 `focus_smooth_frames`（默认 5）帧的中值并以此维护峰值，至少累计 `peak_min_frames`（默认 10）帧有效样本后才有效。每路须先**越峰确认**：峰值出现后清晰度降到 ≤ `focus_pass_percent`（92%）峰值才确认该峰；越峰后往回点动若新平滑峰值超过旧峰不足 `peak_reset_margin_percent`（默认 3.0%，校验 `0 ≤ x < 100 - focus_pass_percent`）则更新峰值并保留确认，超过 ≥ 该比例才视为发现新峰并清除确认。随后往回点动到 ≥ `focus_ready_percent`（95%）且连续 `focus_ready_frames`（5）帧达标，并满足边缘宽度兜底上限 ≤ `focus_max_px`（3.0 px；`focus_good_px` 2.0 / `focus_warn_px` 3.0 仅决定状态条颜色，2.4 px 等黄色可就绪并提示偏宽可接受）且不靠边后，两路都就绪才启用【对刀基准】，点击后实时 XYZ 稳定取均值作为 P0。
4. 某路识别不准时可点该路【人工点选】（按已人工确认参与就绪判定，清晰度与越峰条件仍要满足）或按【识别不准，手动确认】依次点选两台相机针尖；辅助相机点不准可单独【辅助相机手动重设】。换工具或重新开始时点【清晰度峰值清零】同时清零两路峰值。检查像素、清晰度与 P0，按【保存基准】，在新旧值和差值确认框中选择覆盖或不保存。
5. 保存后请电气人员在 PLC 侧记录当前坐标为该工具的对刀基准位置。按【结束/放弃】释放相机。原图、事件、`focus_trace.csv` 和 `session_record.json` 位于运行目录 `baseline/`；保存的基准记录两路目标像素、P0、两路清晰度百分比/边缘宽度/峰值/越峰确认、判定参数和 `baseline_rule: "focus_both_v1"`。换针对刀（100/110 + 40905=2）以基准保存的两路像素为目标。

本流程不通过功能码驱动，仅读取 PLC 实时坐标；保存的雅可比为 null 并标记待测；首次 100/110 经人工逐步确认后自动探测并保存。详见 [现场操作说明](tooltip_baseline_ui.md)。

### 命令行备用工具

现场需要建立含雅可比的旧格式基准时，仍可按原操作使用 `uv run python -m nest_clear.tools.tooltip_baseline --tool 1`。按提示记录 P0、人工点动覆盖三个独立方向并回到 P0，输入补偿，检查拟合 RMS 和条件数后确认保存。工具只读 PLC，不控制运动，也不向 PLC 写入基准。`--verify` 检查基准，`--replay 会话目录` 重算原图，默认不写配置，添加 `--save` 才保存。相机打不开时检查供电、线缆、SN/索引、权限和 SDK；识别失败时检查背光、方向与阈值。相机或设备移动后须重新建立基准。

首次探测相对 P0 分别测量 X、Y、Z 和回 P0 的图像，去均值后用 `fit_view_jacobian` 拟合。检查拟合 RMS、位移矩阵和联合雅可比条件数，保存前将原基准备份到 history。每步及最终对准均需人工确认；超出单步或累计限幅时不能下发，可手动点选重算或放弃。详见 [换针对刀操作说明](tooltip_change_ui.md)。

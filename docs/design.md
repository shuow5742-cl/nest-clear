## 2. 通信约定（协议表：`~/桌面/燕窝挑毛_算法视觉伺服_通信协议V4.0_202610.26_V2.0(1).xlsx`）

- PLC 仍在等待的每个请求必须提交应答：异常回 999，对刀业务失败按协议回 131；写后回读不符也提交错误应答。断线后持续重试。
- 算法端不对等待 PLC 请求设置超时或告警；超时由 PLC 负责。算法端记录通信中断、恢复、持续时间和失败次数，保留心跳事件。采图超时仍作为相机失败处理。


- PLC 192.168.10.10:502，工控机 192.168.10.101。寄存器号 = 地址 − 40001（holding register）。
- 16 位量按 **UINT16**；REAL32 按 **CDAB** 字序（与一代同品牌 PLC，一代实现见 pluck-hair `src/comm/plc_modbus.py`）。
- PLC → PC：40901 设备状态字（位定义见 §3）、40903 Task_ID、40904 功能码、
  40911/13/15 模组 X/Y/Z 实时反馈、40917-40921 1#标定值、40923-40927 2#标定值。
- PC → PLC：40931 心跳（父程序写，0/1 交替，每秒翻转一次）、40932 算法启动完成、40933 Result_ID、40934 功能码、40941 本视野可去数、
  40942/44/46 扫描坐标 XYZ、40948-52 1#标定坐标、40954-58 2#标定坐标、
  40960/62/64 1#工具挑取坐标 XYZ、40966/68/70 2#工具挑取坐标 XYZ。

### 握手（主程序）
- 触发：40903 发生变化且新值 ≠ 0 且 ≠ 上一次已处理值 → 读 40904 功能码 → 分发。
- 应答写入顺序固定：**先写数据区（坐标）→ 再写 40934 功能码 → 最后写 40933 = Task_ID**（40933 是"提交"信号）。
- Task_ID 由 PLC 循环递增（上限不定，回绕到 1）；PLC 每次初始化把 40903 清 0。
- 主程序启动时读取 40903 基线：基线为 0 时清零 40933 和 40934；基线非零且等于 40933 时保持应答区不变；基线非零且未应答时，PLC 不在初始化或急停则回 999，处于初始化或急停则记录被放弃的请求且不写应答区。
- 功能码处理用**分发表**（功能码 → 处理分支），未知功能码回 999 并记录。工作模式使用 1/20/60，对刀使用 100/101/110/120/130。

### 一盘的业务流程（两段定位）

| 状态 | PLC 功能码 | 动作 / 应答 | 下一状态 |
|---|---|---|---|
| IDLE | 1 | 回 1 与首视野粗拍坐标 | WAIT_COARSE |
| WAIT_COARSE | 20 | 到位校验、粗拍识别；写 40941；有可去目标时回 1 与首目标精拍坐标 | WAIT_FINE |
| WAIT_COARSE | 20 | 离开视野：换工具回 10；否则有下一视野回 1，无下一视野回 9 | TOOL_CHANGE / WAIT_COARSE / DONE |
| WAIT_FINE | 20 | 到位校验、精拍识别；成功写两工具坐标并回 3 | WAIT_PICK |
| WAIT_FINE | 20 | 精定位失败，记原因并回 1 与当前视野粗拍坐标 | WAIT_COARSE |
| WAIT_PICK | 60 | 记录挑取完成，回 60，不写坐标与 40941 | WAIT_NEXT |
| WAIT_NEXT | 1 | 名单有剩余且未到上限时回 1 与下个精拍坐标；否则回 1 与当前粗拍坐标 | WAIT_FINE / WAIT_COARSE |
| DONE / TOOL_CHANGE | 任意 | 回 999，等待 PLC 初始化重启 | 原终态 |
| 其他状态 | 不符合该状态的功能码 | 回 999，记录状态、期望与实际功能码 | 原状态 |

IDLE 的 100/101 进入既有对刀分支。到位超差、相机、检测或坐标异常回 999。
粗拍保留 12 步检测、物理门、负责区与针区屏蔽；门通过且未匹配本盘已尝试名单的目标按物理面积降序选前 `max_fine_targets` 个。首拍可去数为 N0，允许尝试次数为 ceil(cap_ratio × N0)。精拍相机 XY 为粗拍模组 XY 加目标工作面坐标与主点工作面投影的差，Z 保持扫描高度。

可选配置 `vision.pick_region_mm` 为模组 XY 矩形 `{x: [xmin, xmax], y: [ymin, ymax]}`，边界包含在内；`null` 不限制。负责区 OTHER 优先，其他候选身份点在范围外标记 out_of_range（蓝框），不计入 40941、N0、前 10 名单或红框，也不参与换工具判定或精定位。粗拍图投影蓝色虚线范围。精定位最终挑点超出范围时记 fine_out_of_range，不下发。检测事件和日报单列范围外数量及原因。

精定位框是主点工作面投影为中心、半宽 `fine_box_half_mm` 的模组坐标正方形。其物理依据为框内深度视差小于 0.1 mm，半宽约为 0.1 × 物距 / 2.5 mm。候选轮廓裁入框后重新取点，取点在框内才可挑；失败分别记 fine_empty、fine_point_outside、fine_rejected、fine_out_of_range，放弃剩余名单并回粗拍。成功时同时写 40960/62/64 与 40966/68/70，由 PLC 选择工具。下一次粗拍中已尝试目标再现为失败，否则为成功。

可去数为零、达到尝试上限后的最终检查、或粗拍次数超过配置上限时离开视野，原因分别记 empty、cap、coarse_limit。尝试次数达到最小值且红框数加可去数大于 tool_check_ratio × N0 时回 10，否则推进视野或回 9。粗拍画面绿为可去、黄为门拒、红为已尝试再现、灰为 OTHER，名单按优先级标序号；精拍画面标框、选中目标及裁后点。

### 坐标
- 全部用**模组坐标系**，单位 mm。扫描坐标 = 相机拍照时模组位置。
- 挑取坐标 = 目标在模组坐标系下的 XY + 工具 i 的 XY 补偿；Z = 下针深度 Z + 工具 i 的 Z 偏移（第一期手填在配置里，工具标定系统做完后替换）。
- 像素→模组坐标：**非远心**针孔模型：内参 K + 畸变 → 射线 → 与工作平面（配置的物面高度）求交，再用手眼外参（相机相对模组的固定位姿，eye-in-hand）加上拍照时的模组实时坐标。标定文件先给占位值 + 合成数据单测。
- 扫描路径：corners 模式保留一代三个角点与步距；tray 模式按料盘角点、尺寸、视野及最小重叠均匀布点。首行沿配置的 Y 方向，换行沿配置的 X 方向，逐行反向。启动事件记录视野、网格、实际重叠和全部中心。
- 负责区：用本帧相机主点投影及扫描坐标差计算各视野中心，仅挑扎点距本中心不大于其他中心距离的目标；其他可挑目标标为 OTHER 并计入检测事件和日报。可通过配置关闭。
- 针区屏蔽：按现场配置的像素矩形丢弃 bbox 中心落入其中的候选，事件记录屏蔽数，叠加图用虚线显示矩形。

## 3. 父程序（supervisor）— 沿用一代规则
40901 位：bit0 手动 bit1 自动 bit2 循环启动 bit3 循环暂停 bit4 循环停止 bit5 上电完成 bit6 急停中
bit7 初始化中 bit8 初始化完成 bit9 信息提示 bit10 一般报警 bit11 严重故障。
- bit7 上升沿 → 启动/重启主程序（**唯一启动入口**）；先停止独立预览进程并确认退出，才清零 40932 并启动主程序。无法确认退出时禁止启动，记录 preview_stop。
- 父程序运行且主程序未运行时可响应界面命令启动独立相机预览进程；主程序运行期间拒绝打开。关闭预览及父程序退出时先请求退出，超时强杀并等待进程退出。父程序通过现有 PLC 连接读取实时 XYZ 并发布，断线显示 --。预览不写生产记录。
- 父程序启动时写 40932=0。父程序拉起主程序前、杀死主程序后及发现意外退出时写 40932=0；主程序预检通过并读取 40903 基线后写 40932=1，再监听请求。
- bit6 → 主程序退出；解除后也要等下一次 bit7，不自动重启。PLC 急停或初始化重启时父程序放弃在途请求，不代回 999，并记录 Task_ID 和功能码；主程序启动时按上述基线规则清零或处理遗留请求。
- 父程序自身退出时，若 PLC 仍等待请求则代回 999；子进程异常退出或看门狗代答失败时持续重试，PLC 进入初始化或急停、40903 清零或改变时立即放弃并记录。
- bit3 / bit4 → 主程序暂停（不 tick 行为树，照常打活性点）；**只有 bit2 能解除**；暂停位与 bit2 同时为 1 时暂停赢。
- bit9/10/11 等：记录进状态文件和日志，不驱动动作（bit11 记 ERROR）。
- 心跳 40931 由父程序写（父程序常驻，主程序重启期间 PLC 不会误判断线）。
- 父→子通道：状态文件（JSON，含 paused）；子→父：活性打点文件；看门狗超时杀子进程。
- 实现参考 pluck-hair `backend/supervisor.py`、`src/supervisor/{device_state,gate,runner}.py`，逻辑等价移植。

## 4. 守卫（必须做到：没碰过项目的人看报错就能定位）
- 统一异常基类 `GuardError(code, what, where, hint)`：错误码（如 `COMM-READ-TIMEOUT`）、发生了什么（带实际值和期望值）、
  在哪（模块/步骤/Task_ID/扫描位序号）、怎么查（下一步该看什么）。中文消息。
- 启动预检：配置校验、PLC 连通、相机按 SN 打开、标定文件存在且形状正确；任何一项失败 → 明确报错退出，不带病运行。
- 运行守卫：坐标落在配置的行程范围内才下发；到位校验；检测输出合法性；未知功能码；Task_ID 异常跳变（记 WARNING）。

## 5. 记录（必须做到：跑一个月仅凭记录知道每天发生了什么）
- 目录 `runs/YYYY-MM-DD/`：`main.log`、`supervisor.log`（按天滚动）；`events.jsonl`（每行一个事件）；`images/`（每个扫描位原图 + 检测叠加图，可配置开关与保留天数）；`summary.json`（每盘：开始/结束时间、扫描位数、挑取次数、999 次数、暂停时长、耗时）。
- 事件至少包括：进程启停（含 git commit、配置摘要）、40901 状态变化（位名人话）、每次握手（Task_ID、收到功能码、回的功能码、坐标、耗时）、到位校验结果、检测结果数、错误、暂停起止。
- 时间统计要扣除暂停时长（一代做法：暂停起止各打一个标记）。

## 6. AutoWeaver 用法
- 主程序 = BTClock + WorldBoard + Workers（plc / camera / vision）+ 每盘一个 Batch（行为树）。
- 树负责"流程"（等请求 → 分发 → 动作 → 应答），Worker 负责"能力"（读写 PLC、拍照、检测）；树与 Worker 之间只经 note/state 通信（NotifyAndWait 等）。
- 参考 pluck-hair 的 `main.py` 装配方式与 `src/pluck/flow.py`、`src/workers/*.py` 的写法；框架注意事项见 `~/docs/code-guides/autoweaver.md`（完成≠成功，要另查错误；同步 handler 会阻塞全局 tick）。
- 发现框架缺的通用能力：先在 nest-clear 里实现，同时记入 `docs/framework-candidates.md`（为什么通用、建议放框架哪里）。**不要直接改 ~/Auto_Weaver**，除非任务明确要求。

## 7. 代码风格（所有任务必须遵守）
- 一行一条语句；禁止分号连写、禁止 `if x: do()` 同行写法。
- 所有函数有类型标注 + 中文 docstring（做什么、为什么这样、和谁衔接）；模块顶部写模块说明。
- 关键决策处写注释解释原因；写法参照 pluck-hair `backend/src/supervisor/gate.py`。
- 所有可预期的失败抛 `GuardError`（不要裸 ValueError/RuntimeError），带实际值、上下文（Task_ID/扫描位序号等）和具体 hint。
- logging 的 logger 名用 `nest_clear.<模块>`；中文日志。
- 测试：`uv run --extra dev pytest -q`；新功能必须带测试。不新增依赖、不改 pyproject.toml（确需新增先问 Claude）。

## 8. 坐标符号约定（T3 起生效）
- 视觉输出的目标坐标 = "相机参考点对准该目标时的模组坐标"（模组坐标系，mm）。

## 9. 工具标定（对刀）协议（2026-11-04 用户定稿，Claude 补全边界）

基准（RoboCal 独立工具建立，PLC 与算法各存一份）：每把工具 i∈{1,2} 一份记录——P0ᵢ（人工标定时针尖到达两台标定相机标定像素位置的模组坐标）、
两台相机的标定像素位置、两台相机的 像素/mm 换算矩阵（2×3）、人工定的基准 X/Y 补偿与基准下针深度。

| | 工具1 | 工具2 |
|---|---|---|
| PLC 开始（已在 P0ᵢ） | 40904=100 | 101 |
| PLC 偏移到位 | 110 | 120 |
| PC 首次需要偏移（带坐标） | 回 100 | 回 101 |
| PC 后续仍需偏移（带坐标） | 回 110 | 回 120 |
| PC 到位、本工具结束 | 回 111 | 回 121 |
| PC 写偏移坐标的地址 | 40948-40952 | 40954-40958 |
| PLC 最终标定坐标 | 40917-40921 | 40923-40927 |

流程：
1. 收到 100/101：读 40911-15 实时坐标与 P0ᵢ 比，任一轴超 `position_tolerance_mm`（默认 0.05）→ 回 131。
2. 两台标定相机拍照 → 识别针尖像素 → 由两台相机的像素偏差最小二乘解出模组修正量 Δ(x,y,z)（正面相机看 X/Z、侧面看 Y/Z；Z 以正面为准，两相机 Z 分歧超阈值记 WARNING）。
3. |残差| 都在 `tip_tolerance_mm`（默认 0.03）内 → 回 111/121；否则 新坐标 = 当前坐标 + 修正量，行程守卫，写偏移地址，回 100/101（本次第一次偏移）或 110/120（之后）。
4. 收到 110/120：读实时坐标与上次写的偏移坐标比（超 position_tolerance_mm → 131），再回到第 2 步。偏移次数超过 `max_iterations`（默认 10）→ 131。认不出针尖 → 131。
5. 收到 130：须有已结束(111/121)的本次标定会话，否则 131。期望坐标 = 本次最后写的偏移坐标（无偏移时 = P0ᵢ）。
   读 PLC 最终坐标(40917-21 / 40923-27)：有偏移时与期望逐轴差 ≤ `consistency_tolerance_mm`（默认 0.01）；无偏移时用 position_tolerance_mm，并同时核对 40911-15 实时坐标与 P0ᵢ。
   一致 → 先计算并保存补偿，再回 130；不一致 → 131。
6. 补偿：Δ = P_final − P0ᵢ；新 X/Y 补偿 = 基准 X/Y 补偿 + Δxy；新下针深度偏移 = 基准值 + Δz。
   保存到 `config/calibration/tools.yaml`：原子写入，写前备份旧版，追加历史记录（时间、工具号、P_final、Δ、新旧补偿）；运行中的主程序立即使用新值。
7. **工作模式（11-04 用户定）**：主程序始终处于四种模式之一，分发表每项声明“允许的模式”，不符一律回 999 并记日志（写明当前模式、盘号、扫描位、收到的功能码）：

   | 模式 | 进入条件 | 允许的功能码 |
   |---|---|---|
   | 空闲 | 主程序启动；回 9 之后；回 130/131、81/82 或 91/92 之后 | 1（开始一盘）、80（相机标定）、90（工具偏移标定）、100/101（开始对刀） |
   | 挑毛中 | 回出第一个扫描坐标之后，直到 PLC 初始化 | 1、20、60 |
   | 相机标定中 | 收到 80 开始，直到回 81/82 或会话中断 | 80 |
   | 工具偏移标定中 | 收到 90 开始，直到回 91/92 或会话中断 | 按顺序交替 95、90 |
   | 对刀中(工具 i) | 收到 100/101 且通过到位校验后，直到回 130/131 | 110(i=1)/120(i=2)、130 |

   - 挑毛中或对刀中收到 80 → 999，须先结束当前模式；相机标定中收到非 80 → 999 并结束会话，记录 camcal_aborted。PLC 初始化或急停中断会话且不应答，记录 request_abandoned。
   - 挑毛中收到 100/101 → 999（挑毛进行中对刀不合理，须先停止挑毛）；对刀中收到 1/20/60、工具号不符的 110/120、无会话的 110/120/130 → 999。
   - 对刀业务失败（未在初始位置、到位校验失败、超迭代、认不出针尖、130 不一致、补偿保存失败）→ 131，回到空闲。
   - **PLC 约定：对刀前 PLC 会重新初始化**（bit7 → 父程序重启主程序 → 空闲模式）。因此父程序“暂停/停止冻结主程序”的规则不变。
   - 代码组织：`flow/modes.py` 只放模式与合法切换（纯规则，可单测）；分发表项 = (功能码, 允许模式, 子树工厂)，模式检查由分发统一完成；挑毛分支 `flow/picking.py`、对刀分支 `flow/calibration.py`，互不引用，共用唯一应答出口；每次模式切换写事件。
   - 通信异常/未知功能码仍回 999。

对刀算法及接口说明见 [docs/tooltip.md](tooltip.md)，实现位于 `src/nest_clear/tooltip/`。

### 换针对刀人工确认与首次探测

100/101 校验 P0 并采集双视图后，PLC 请求保持挂起，界面确认后才应答；每次移动及最终结果均须人工确认，不设算法等待超时。确认首次移动回 100/101，后续移动回 110/120；确认对准回 111/121，放弃回 131。识别位置不准可在当前双视图帧上手动点选并重算。PLC 130 仍核对最终坐标与最后一次实际下发的坐标，保存补偿后回 130；不一致回 131。

雅可比为空时，先从 P0 分别移动至 P0 + 0.2 mm 的 X、Y、Z 位置并回 P0，每一步均确认、下发及到位校验后采图。样本拟合两视图雅可比，检查像素残差和条件数，合格后备份旧基准到 history 并原子写入；不合格回 131。探测四次不占正常对准的迭代次数。单步任一轴超过 `max_step_mm`（默认 0.5）或目标相对 P0 任一轴超过 `max_total_mm`（默认 2.0）禁止下发，等待手动点选或放弃；探测步长由 `probe_step_mm` 配置（默认 0.2）。范围判断采用 `tip_tolerance_mm`（默认 0.03）。事件和会话记录保留原图、识别、人工点及确认坐标与时间。



## 对刀基准建立（界面）

主程序空闲时界面开始会话并选择工具；主对刀相机使用现有 front，辅助对刀相机使用 side。会话中所有 PLC 功能码回 999，原因“对刀基准建立中，请先在界面结束”，不会结束会话；挑毛或其他标定中忽略界面开始。两相机由主程序持有，会话后台线程取图与识别，结束和异常时释放；换针对刀下次使用时重新打开。人工通过 PLC 手动点动；此功能不向 PLC 写运动或基准地址。

`config/tooltip_baseline.yaml` 的 `baseline_ui` 设置主相机目标（默认图像中心）、容许半径 0.05 mm 和两相机比例（默认 15.2 μm/px，8 mm 镜头估算值待实测）。主视图实时标记与偏差只作辅助。按对刀基准时，两视图均需识别及清晰度合格，主针尖在圆内；按工具偏移标定的稳定采样参数读取实时 XYZ，稳定后均值为 P0。人工点选可替换两视图针尖，辅助重设只修改辅助点。

覆盖前显示新旧时间、P0、像素和差值；保存时绑定 `tools.yaml` 当时的补偿，备份到 `history/`，清除该工具 `tool_offset.yaml` 的 `baseline_stale`。使用配置的标定目录；会话原图和记录保存在运行目录 `baseline/`。界面保存的雅可比为 null，`jacobian_pending: true`；首次换针对刀时自动探测并保存雅可比，已有雅可比直接对准。原有含雅可比的基准及命令行工具保留。

## 相机标定模式

PLC 在空闲发送 40904=80。算法读取 40911/40913/40915 实时 XYZ，与配置的起始位逐轴比较；未到位时第一次 80 回起始坐标，到位后再发 80 并检查到位，随后以实测位置为起始位拍首图；每次需要移动时将目标 XYZ 以 REAL32 CDAB 连续写入 40972/40974/40976，40934 回 80，PLC 到位后再次发送 80。算法逐轴核对实时坐标，超出 position_tolerance_mm 回 999 并结束会话；到位后拍下一张。目标须同时满足相对起始位 xy_limit_mm/z_limit_mm 及绝对 travel 行程。成功保存并热更新标定后回 81；业务失败回 82 并结束会话。PLC 收到 81/82 后结束标定流程。82 是用户已定的失败码，等待电气补入协议表。

失败码由标定会话提供：CAMCAL-GLARE（亮斑是角点覆盖不足的主要原因）、CAMCAL-NO-BOARD（未检出标定板）、CAMCAL-OFFCENTER（板位置不合适）、CAMCAL-OVEREXPOSED（全图过曝）、CAMCAL-COVERAGE（覆盖不足）、CAMCAL-RMS（重投影误差超限）、CAMCAL-REPEAT（重复性超限）、CAMCAL-AXIS-SCALE（轴比例误差超限）、CAMCAL-SOLVE（求解失败）；采图、目标行程守卫和保存异常也回 82 并记录原因。每张图记录 camcal capture、步骤与标注，会话观测写入运行目录 camcal/<会话时间>/session_record.json。PLC 初始化或急停沿用父程序中断规则，不对被放弃的请求应答。

### 可靠性判定与人工点击兜底

每轮检查检测失败、粗定位、针尖宽度与基准相差超过 30%、双视图 Z 分歧、求解残差和条件数；对准的最终轮还检查清晰度。基准缺少宽度时跳过宽度比较。`quality_hard_fail=false` 时残差、条件数和 Z 分歧只告警，检测层判据仍触发不可靠处理。换针对刀中识别不可靠时禁止下发，操作员可主动打开独立进程中的两视图点选或放弃；主行为树持续 tick，等待确认不设算法超时。识别不到针尖时返回 131。人工点替换检测点后重新求解并检查几何质量。点击事件及修正量写入记录和日报。基准工具参考帧必须确认，`--no-confirm` 仅供模拟测试；步进帧检测失败或离焦时也请求确认。

## 工具偏移标定（90/95/91/92）

空闲收到 90 后建立会话，等待界面选择工具和模式并按开始；没有算法超时。确认起始坐标和相机标定有效后，将 `camera_calibration.start_xyz` 以 REAL32 CDAB 写入 40972/40974/40976，再回 90。PLC 到位发 95；算法检查停稳和到位，拍总览照并检出至少两个靶点，以目标模组坐标与菲林名义坐标拟合平移、旋转和统一尺度；尺度偏离 1 超过 3% 回 92。总览后回 95。此后 PLC 发 90，算法写下一拍照坐标并回 90；PLC 到位发 95。95 请求只回 95（继续）、91（成功）或 92（业务失败），绝不回 90。

各目标按 `tool_offset.point_order` 顺序采集。圆环偏离主点超过 `center_tol_mm` 时，修正坐标并回 95；最多修正两次。对中后等待人工移动选定工具并按工具到位，计算工具实时 XY 减目标 XY。超过 `outlier_mm` 的样本剔除并追加一次重测；有效点至少 `min_points` 且 X/Y 标准误都不大于 `se_tol_mm` 才能进入成功候选。达到 `max_points` 或队列耗尽仍不收敛回 92。行程外目标跳过并记录；工具预测行程使用当前有效偏移均值。

中心+边缘模式在成功候选前将已测目标依次放在画面四角附近采图，比较边缘坐标和中心坐标，不移动工具、不参与平均。差值大于 `edge_warn_mm` 告警但不判失败。ArUco 指示目标身份和局部方向，圆环亚像素椭圆中心作为结果，十字中心偏差超过 `ring_cross_tol_mm` 记录质量警告，超过两倍则回 92。相机求解器的工作面是标定板上表面；目标平面沿朝模组 Z 正方向的板面法向移动 `card_thickness_mm - camera_calibration.board_thickness_mm`。板厚应填写相机标定时板面距料盘面的总厚度。

95 到位检查和人工工具到位都在 `settle_window_s` 内采集 `settle_samples` 次实时 XYZ，逐轴极差不大于 `jitter_tol_mm` 才取均值；最多三轮。95 不稳或与目标逐轴差超过 `camera_calibration.position_tolerance_mm` 回 999；工具到位不稳时保持请求未应答并等待重新按键。无会话收到 95、会话中错序 90、其他工作模式收到 90/95、起始坐标未配置、相机标定不存在、到位超差均回 999 并结束会话。PLC 初始化或急停沿用 request_abandoned。

确认窗口展示新旧结果、差值和 `tools.yaml` 当前 XY；不保存或放弃回 92。覆盖保存将旧文件备份到 `history/`，写入 `tool_offset.yaml` 的本工具结果并保留另一把，同时将 `tools.yaml` 的本工具 XY 替换为新补偿，保留 Z 并热更新。结果包括样本、标准差、标准误、边缘结果、相机文件 SHA-256、commit、时间及 `baseline_stale: true`。这把工具的对刀基准不会自动修改，换针对刀前需重建基准。标定文件使用 `config/calibration/`。

界面命令文件为记录目录的 `live/command.json`，原子写入 `{seq, command, params, time}`；命令名为 `select_tool_and_start`（tool、mode）、`tool_in_place`、`confirm_overwrite`（accept）、`abort`。主程序按 seq 去重，在 `state/main_status.json` 的 `command_seq` 回执；非等待态命令忽略并记事件。行为树持续 tick，等待不阻塞心跳。原图、识别、阶段、请求、应答、命令和会话记录写入运行目录。

### 挑取精度标定（150/155/156）

空闲 150 建立会话，等待界面选工具后回 150 和起始相机位。155 检查稳定到位并采图：总览或需要对中时回 150 和新相机位；目标就位时只写所选工具挑取坐标并回 155。156 等待人工对准；计算后继续回 156、失败回 152，成功候选经覆盖确认并保存后回 151。错序和相机到位超差回 999。回 156 后下一请求为 150。算法不设置人工操作超时。

总览拟合菲林片位姿，测点对中、圆环中心投影使用工具偏移标定的识别和平面模型。9 个中心点及 T12 四角检查后选择固定补偿或扩展至 16 点及重复性检查。表采用 Delaunay 分段线性插值，凸包外用最近节点；验证点不参与拟合。工具2 在工具1标定快照仍匹配时可先试五点差值简化流程。原始测点、视野内检查、验证、配置快照和版本写入结果与会话记录；确认后原子保存并备份。生产坐标按工具叠加目标位置补偿，记录每次使用的补偿。

相机标定按板区饱和连通域分析亮斑：距饱和像素不超过 `glare_corner_margin_px` 的漏检角点归因于亮斑，同距离的已检出角点剔除。该值为 null 时自动取相邻预测角点间距中位数的 1/4，也可配置非负整数像素。剔除后仍达到 `min_corner_ratio` 的图继续参与求解并记录 `camcal_glare_warning`；不足时按亮斑损失是否占主要部分区分 CAMCAL-GLARE 和 CAMCAL-COVERAGE。`max_saturated_fraction` 的整体过曝检查仍独立生效。每张图的 detail 记录漏检 ID、各连通域 bbox、面积及归因和剔除 ID。旧配置 `glare_min_lost_corners` 为兼容保留，不再触发直接失败。

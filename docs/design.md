**保留**守卫详细、记录详细、父子进程结构；**改掉**一代的已知毛病（配置入口散乱、注释新旧混杂、

## 2. 通信约定（协议表：`~/桌面/燕窝挑毛_算法视觉伺服_通信协议V4.0_202610.26_V1.0.xlsx`）

- PLC 192.168.10.10:502，工控机 192.168.10.101。寄存器号 = 地址 − 40001（holding register）。
- 16 位量按 **UINT16**；REAL32 按 **CDAB** 字序（与一代同品牌 PLC，一代实现见 pluck-hair `src/comm/plc_modbus.py`）。
- PLC → PC：40901 设备状态字（位定义见 §3）、40903 Task_ID、40904 功能码、
  40911/13/15 模组 X/Y/Z 实时反馈、40917-40921 1#标定值、40923-40927 2#标定值。
- PC → PLC：40931 心跳（父程序写，1Hz 翻转/递增）、40933 Result_ID、40934 功能码、
  40942/44/46 扫描坐标 XYZ、40948-52 1#标定坐标、40954-58 2#标定坐标、
  40960/62/64 1#工具挑取坐标 XYZ、40966/68/70 2#工具挑取坐标 XYZ。

### 握手（主程序）
- 触发：40903 发生变化且新值 ≠ 0 且 ≠ 上一次已处理值 → 读 40904 功能码 → 分发。
- 应答写入顺序固定：**先写数据区（坐标）→ 再写 40934 功能码 → 最后写 40933 = Task_ID**（40933 是"提交"信号）。
- Task_ID 由 PLC 循环递增（上限不定，回绕到 1）；PLC 每次初始化把 40903 清 0。
- 主程序启动：先写 40933=0、40934=0；以当时 40903 为基线。若基线 ≠ 0，记 WARNING（遗留未应答请求）并忽略，只响应之后的变化。
- 功能码处理用**分发表**（功能码 → 处理分支），未知功能码回 999 并记录。后续功能码（20/10/61/工具标定 100-131）只往表里加分支。

### 一盘的业务流程（第一期）
- 收到 1，且本盘尚未发过扫描坐标 → 回 1 + 第一个扫描坐标（不拍照）。
- 收到 1，且上次回的是扫描坐标 → 设备已到该扫描位：
  1. 读 40911-15 实时坐标，与下发的扫描坐标比较，任一轴超公差（配置项）→ 回 999。
  2. 拍照 → 检测 → 得到本扫描位的目标列表（按配置排序/去重，最多 N 个）。
  3. 有目标 → 取第一个，回 3 + 挑取坐标（写入当前工具对应地址）；无目标 → 回 1 + 下一扫描坐标；已无扫描坐标 → 回 9。
- 收到 60（挑取完成下一步）→ 本扫描位目标列表还有剩余 → 回 3 + 下一个挑取坐标（工具交替）；否则同上回 1 下一扫描坐标或 9。
- **挑完不重新拍照**（用户 11-03 定，后续测试发现带动别的毛再改）。
- 工具交替：每发一次 3 就切换 1#↔2#；跨扫描位继续交替；每盘从 1# 开始（一盘结束设备换盘后重新初始化）。
- 回 9 之后本盘 Batch 结束；主程序继续等待（下一盘由 PLC 初始化→父程序重启主程序开始）。
- 相机/检测/坐标换算异常 → 回 999，原因进日志与事件记录。

### 坐标
- 全部用**模组坐标系**，单位 mm。扫描坐标 = 相机拍照时模组位置。
- 挑取坐标 = 目标在模组坐标系下的 XY − 工具 i 的 XY 补偿；Z = 下针深度 Z + 工具 i 的 Z 偏移（第一期手填在配置里，工具标定系统做完后替换）。
- 像素→模组坐标：**非远心**针孔模型：内参 K + 畸变 → 射线 → 与工作平面（配置的物面高度）求交，再用手眼外参（相机相对模组的固定位姿，eye-in-hand）加上拍照时的模组实时坐标。标定文件先给占位值 + 合成数据单测。
- 扫描路径：与一代相同 —— 配置给三个角点 + X/Y 步距，生成蛇形路径（参考 pluck-hair `src/pluck/flow.py` 的 build_serpentine_path）。

## 3. 父程序（supervisor）— 沿用一代规则
40901 位：bit0 手动 bit1 自动 bit2 循环启动 bit3 循环暂停 bit4 循环停止 bit5 上电完成 bit6 急停中
bit7 初始化中 bit8 初始化完成 bit9 信息提示 bit10 一般报警 bit11 严重故障。
- bit7 上升沿 → 启动/重启主程序（**唯一启动入口**）。
- bit6 → 主程序退出；解除后也要等下一次 bit7，不自动重启。
- bit3 / bit4 → 主程序暂停（不 tick 行为树，照常打活性点）；**只有 bit2 能解除**；暂停位与 bit2 同时为 1 时暂停赢。
- bit9/10/11 等：记录进状态文件和日志，不驱动动作（bit11 记 ERROR）。
- 心跳 40931 由父程序写（父程序常驻，主程序重启期间 PLC 不会误判断线）。
- 父→子通道：状态文件（JSON，含 paused）；子→父：活性打点文件；看门狗超时杀子进程。
- 实现参考 pluck-hair `backend/supervisor.py`、`src/supervisor/{device_state,gate,runner}.py`，逻辑等价移植。

## 4. 守卫（必须做到：没碰过项目的人看报错就能定位）
- 统一异常基类 `GuardError(code, what, where, hint)`：错误码（如 `COMM-READ-TIMEOUT`）、发生了什么（带实际值和期望值）、
  在哪（模块/步骤/Task_ID/扫描位序号）、怎么查（下一步该看什么）。中文消息。
- 启动预检：配置校验、PLC 连通、相机按 SN 打开、标定文件存在且形状正确；任何一项失败 → 明确报错退出，不带病运行。
- 运行守卫：坐标落在配置的行程范围内才下发；到位校验；检测输出合法性；未知功能码；Task_ID 异常跳变（记 WARNING）。

## 5. 记录（必须做到：跑一个月仅凭记录知道每天发生了什么）
- 目录 `runs/YYYY-MM-DD/`：`main.log`、`supervisor.log`（按天滚动）；`events.jsonl`（每行一个事件）；`images/`（每个扫描位原图 + 检测叠加图，可配置开关与保留天数）；`summary.json`（每盘：开始/结束时间、扫描位数、挑取次数、999 次数、暂停时长、耗时）。
- 事件至少包括：进程启停（含 git commit、配置摘要）、40901 状态变化（位名人话）、每次握手（Task_ID、收到功能码、回的功能码、坐标、耗时）、到位校验结果、检测结果数、错误、暂停起止。
- 时间统计要扣除暂停时长（一代做法：暂停起止各打一个标记）。

## 6. AutoWeaver 用法
- 主程序 = BTClock + WorldBoard + Workers（plc / camera / vision）+ 每盘一个 Batch（行为树）。
- 树负责"流程"（等请求 → 分发 → 动作 → 应答），Worker 负责"能力"（读写 PLC、拍照、检测）；树与 Worker 之间只经 note/state 通信（NotifyAndWait 等）。
- 参考 pluck-hair 的 `main.py` 装配方式与 `src/pluck/flow.py`、`src/workers/*.py` 的写法；框架注意事项见 `~/docs/code-guides/autoweaver.md`（完成≠成功，要另查错误；同步 handler 会阻塞全局 tick）。
- 发现框架缺的通用能力：先在 nest-clear 里实现，同时记入 `docs/framework-candidates.md`（为什么通用、建议放框架哪里）。**不要直接改 ~/Auto_Weaver**，除非任务明确要求。

## 7. 代码风格（所有任务必须遵守）
- 一行一条语句；禁止分号连写、禁止 `if x: do()` 同行写法。
- 所有函数有类型标注 + 中文 docstring（做什么、为什么这样、和谁衔接）；模块顶部写模块说明。
- 关键决策处写注释解释原因；写法参照 pluck-hair `backend/src/supervisor/gate.py`。
- 所有可预期的失败抛 `GuardError`（不要裸 ValueError/RuntimeError），带实际值、上下文（Task_ID/扫描位序号等）和具体 hint。
- logging 的 logger 名用 `nest_clear.<模块>`；中文日志。
- 测试：`uv run --extra dev pytest -q`；新功能必须带测试。不新增依赖、不改 pyproject.toml（确需新增先问 Claude）。

## 8. 坐标符号约定（T3 起生效）
- 视觉输出的目标坐标 = "相机参考点对准该目标时的模组坐标"（模组坐标系，mm）。
- 挑取坐标：pick_xy = target_xy + tool_i.xy；pick_z = pick_depth_z + tool_i.z。
  tool_i.xy 的含义 = 针尖相对相机参考点的偏移（模组坐标系），第一期人工测定填入配置。

## 9. 工具标定（对刀）协议（2026-11-04 用户定稿，Claude 补全边界）

基准（RoboCal 独立工具建立，PLC 与算法各存一份）：每把工具 i∈{1,2} 一份记录——P0ᵢ（人工标定时针尖到达两台标定相机标定像素位置的模组坐标）、
两台相机的标定像素位置、两台相机的 像素/mm 换算矩阵（2×3）、人工定的基准 X/Y 补偿与基准下针深度。

| | 工具1 | 工具2 |
|---|---|---|
| PLC 开始（已在 P0ᵢ） | 40904=100 | 101 |
| PLC 偏移到位 | 110 | 120 |
| PC 首次需要偏移（带坐标） | 回 100 | 回 101 |
| PC 后续仍需偏移（带坐标） | 回 110 | 回 120 |
| PC 到位、本工具结束 | 回 111 | 回 121 |
| PC 写偏移坐标的地址 | 40948-40952 | 40954-40958 |
| PLC 最终标定坐标 | 40917-40921 | 40923-40927 |

流程：
1. 收到 100/101：读 40911-15 实时坐标与 P0ᵢ 比，任一轴超 `position_tolerance_mm`（默认 0.05）→ 回 131。
2. 两台标定相机拍照 → 识别针尖像素 → 由两台相机的像素偏差最小二乘解出模组修正量 Δ(x,y,z)（正面相机看 X/Z、侧面看 Y/Z；Z 以正面为准，两相机 Z 分歧超阈值记 WARNING）。
3. |残差| 都在 `tip_tolerance_mm`（默认 0.03）内 → 回 111/121；否则 新坐标 = 当前坐标 + 修正量，行程守卫，写偏移地址，回 100/101（本次第一次偏移）或 110/120（之后）。
4. 收到 110/120：读实时坐标与上次写的偏移坐标比（超 position_tolerance_mm → 131），再回到第 2 步。偏移次数超过 `max_iterations`（默认 10）→ 131。认不出针尖 → 131。
5. 收到 130：须有已结束(111/121)的本次标定会话，否则 131。期望坐标 = 本次最后写的偏移坐标（无偏移时 = P0ᵢ）。
   读 PLC 最终坐标(40917-21 / 40923-27)：有偏移时与期望逐轴差 ≤ `consistency_tolerance_mm`（默认 0.01）；无偏移时用 position_tolerance_mm，并同时核对 40911-15 实时坐标与 P0ᵢ。
   一致 → 先计算并保存补偿，再回 130；不一致 → 131。
6. 补偿：Δ = P_final − P0ᵢ；新 X/Y 补偿 = 基准 X/Y 补偿 + Δxy；新下针深度偏移 = 基准值 + Δz。
   保存到 `config/calibration/tools.yaml`：原子写入，写前备份旧版，追加历史记录（时间、工具号、P_final、Δ、新旧补偿）；运行中的主程序立即使用新值。
7. **工作模式（11-04 用户定）**：主程序始终处于三种模式之一，分发表每项声明“允许的模式”，不符一律回 999 并记日志（写明当前模式、盘号、扫描位、收到的功能码）：

   | 模式 | 进入条件 | 允许的功能码 |
   |---|---|---|
   | 空闲 | 主程序启动；回 9 之后；回 130/131 之后 | 1（开始一盘）、100/101（开始对刀） |
   | 挑毛中 | 回出第一个扫描坐标之后，直到回 9 | 1、60 |
   | 对刀中(工具 i) | 收到 100/101 且通过到位校验后，直到回 130/131 | 110(i=1)/120(i=2)、130 |

   - 挑毛中收到 100/101 → 999（挑毛进行中对刀不合理，须先停止挑毛）；对刀中收到 1/60、工具号不符的 110/120、无会话的 110/120/130 → 999。
   - 对刀业务失败（未在初始位置、到位校验失败、超迭代、认不出针尖、130 不一致、补偿保存失败）→ 131，回到空闲。
   - **PLC 约定：对刀前 PLC 会重新初始化**（bit7 → 父程序重启主程序 → 空闲模式）。因此父程序“暂停/停止冻结主程序”的规则不变。
   - 代码组织：`flow/modes.py` 只放模式与合法切换（纯规则，可单测）；分发表项 = (功能码, 允许模式, 子树工厂)，模式检查由分发统一完成；挑毛分支 `flow/picking.py`、对刀分支 `flow/calibration.py`，互不引用，共用唯一应答出口；每次模式切换写事件。
   - 通信异常/未知功能码仍回 999。

对刀算法及接口说明见 [docs/tooltip.md](tooltip.md)，实现位于 `src/nest_clear/tooltip/`。

# 框架候选能力

- `CommEngine` 的 REAL32 块写入目前固定校验六个位姿字段，不能直接表达本项目的 XYZ 三轴块。建议在框架通信原语中支持按 `BlockSpec.order` 声明任意字段的块；这种能力也适用于其他三轴设备。本项目先用 `RegisterIO` 接口实现握手。

- 异步感知和通信命令需要在后台任务成功或失败后才确认完成；当前 `PerceptionWorker` 的 handler 返回即完成语义容易提前确认。建议在 Worker 层提供通用的异步请求完成协议，并让等待节点可检查对应请求的错误；相机、网络 IO 和推理都可复用。

- `NotifyAndWait` 只等待完成编号，不能验证与该编号对应的成功或失败及获取结果；`CallWorker` 在应用中补充逐请求结果和错误检查。建议框架提供可组合的异步调用叶及明确的结果关联协议，供 PLC、相机和算法调用复用。
- 框架组合节点已暴露 `children` / `child`，但缺少面向现场日志的统一缩进树结构输出。建议提供只读的树遍历与格式化 API，便于多个应用在启动时核对流程。
